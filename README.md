## Who I am

I turn a repetitive routine into a system, and into a job the team can run without opening an IDE.

Someone starts the work from a panel, a spreadsheet, or a request in the app. The program validates the input, walks the flow through a browser or an API, writes the result back, and leaves a log, evidence, and a resume point if the batch stops halfway.

## How a flow starts

<table>
<tr><th align="left">Step</th><th align="left">What happens</th><th align="left">Where the result lives</th></tr>
<tr><td>1. Input</td><td>Spreadsheet, queue, or a validated form</td><td>File or record that passed the schema</td></tr>
<tr><td>2. Execution</td><td>Browser, API call, or a background worker</td><td>One item at a time, resumable</td></tr>
<tr><td>3. Record</td><td>The return is saved. One failure is marked and the batch continues</td><td>Sheet, database, or screen</td></tr>
<tr><td>4. Proof</td><td>Run log, and a screenshot when the flow needs evidence</td><td>The day's folder, next to the program</td></tr>
<tr><td>5. Operation</td><td>The team starts it from the panel or the executable</td><td>No IDE on the operator's machine</td></tr>
</table>

<a id="how-i-build"></a>

## How I build

<table>
<tr><th align="left">Principle</th><th align="left">In practice</th></tr>
<tr><td>Clear layers</td><td>Screen at the edge, rules in a service, data in the database</td></tr>
<tr><td>Separate environments</td><td>Real secrets stay out of the repository. Development and production use different databases and keys</td></tr>
<tr><td>Resumable batches</td><td>A finished item stays marked. One failed item is logged and the rest continues</td></tr>
<tr><td>Explicit waits</td><td>Stable selectors and a timeout. No fixed sleep as the sync mechanism</td></tr>
<tr><td>Credentials outside the code</td><td>The operator types them in, or the process reads local configuration</td></tr>
<tr><td>Checks on the server</td><td>Parameterized queries, form protection, secure cookies, attempt limits, and uploads capped by size and type</td></tr>
<tr><td>Work off the request</td><td>Redis and Celery for jobs that must not block the HTTP response</td></tr>
<tr><td>Release</td><td>Container image, TLS at the proxy, health check, and migration as part of deploy</td></tr>
</table>
